## Hardware Today

We have horizontally scaled rather than vertically scaled systems over time; quad cores have become the norm. Coming to the structure of the system, we have CPUs, Northbridge, and Southbridge. The Northbridge is responsible for the memory controller, which helps in working with RAM, and it is connected to every CPU through a bus (front-side bus). The Southbridge is responsible for working with I/O devices using buses like SATA, PCI-Express, USB, etc. All communication with devices passes through the Northbridge and Southbridge and then to the CPUs; all communication with RAM passes through the Northbridge. Communication between CPUs also goes through the Northbridge.

Few bottlenecks: any device that wants to communicate with RAM for data or any task has to go through the CPU, putting a burden on the CPU. In order to solve this, we introduce DMA (Direct Memory Access), which allows communication to occur without the need for CPU involvement, though this causes contention between DMA and CPU. The other bottleneck is the bus from the Northbridge to RAM; it is a shared bus with limited parallel access. But these days we have improved buses (DDR2, etc.) which increase bandwidth, and the Northbridge can interleave memory access across channels.

Now we involve multiple cores, hyper-threads, and processors trying to access RAM, so we need a way to schedule access in order to decrease latency; this is true for DMA as well. We also factor in the concept of access patterns when designing systems. We have other ways to increase bandwidth also; instead of attaching the memory controller to the Northbridge, we use a separate controller (not only in the Northbridge anymore), which helps in attaching the RAM. So now we can attach multiple of them, allowing for better access time in concurrent situations (access patterns) and across cores, by accessing multiple memory banks at once. The only issue is with the internal Northbridge bandwidth here.

Now, a more popular method (SMP systems, AMD’s Opteron processor) is to attach the memory controller and memory directly to the CPU instead of the Northbridge. Now the memory bandwidth is effectively increased (e.g., for quad cores), and this is called NUMA systems. The obvious drawback is that, while we want the system to behave as if memory access is uniform, the access time is non-uniform, since there is a difference between accessing local memory and accessing memory of another CPU, which requires going across connecting buses (multiple hops depending on cores and interconnects, e.g., IBM x445).

### RAM TYPES

Mention of SRAM and DRAM: the main reason we do not use SRAM for everything is cost and higher power consumption. SRAM is made up of 6 transistors (two cross-coupled inverters) and requires constant power for maintaining the stored state. We have variants with speed trade-offs, etc., not very important here. Also, in order to read and write, we use the word line and bit line; we read when the word line allows access, and the bit line difference contains the cell state. When we want to write to the cell, we charge up the bit line and open the word line, and due to reverse flow from the bit line we write into the cell.

DRAMs are more complicated, use less space than SRAM, and consume less energy, but require constant refresh as charge dissipates quickly. Coming to the details, because of the need for periodic refresh (which affects reading and writing capability), we have a refresh window of about 64 ms. Also, as charge builds up and dissipates, it requires time, which delays operations (it is not instantaneous like SRAM), and when we read the cell state we need to restore it again for subsequent operations.

Some more details: when we want to access DRAM, our virtual memory address is converted to a physical address, goes to the memory controller first, and after that it would naively require many lines (e.g., 32 bits → 32 lines), which does not scale well. So we encode and multiplex to reduce the number of lines; it is very difficult to maintain ~30 parallel signals compared to ~15. Another problem is that there is a delay when we update or access the cell state after using RAS and CAS, so the system must wait for these delays to ensure correctness. Also, needing ~30 address lines just to access RAM modules (RAM → modules → chips) is not feasible, especially if we want parallel access. To solve this, DRAM multiplexes the address internally using RAS and CAS, along with control lines to indicate operations.

---

DRAM Technical details: we are mainly looking at SDRAM (Synchronous DRAM) and DDR. In SDRAM, we have a clock frequency provided by the memory controller, and it determines the speed of the FSB (interface between Northbridge, CPUs, and RAM). Today’s buses are double or quad pumped, so we can push 2× or 4× the amount of data.

Read access protocol: we use RAS, CAS, address bus, data bus, and CLK. We read on rising edges of CLK, and we assert/deassert RAS & CAS signals when we receive the required row or column address. We have tRCD, which is the time after which we can send the column address (after sending the row address). After obtaining both, we have another wait time (CAS latency) before data is returned. We can also keep the row open (RAS active) and send multiple CAS signals to get sequential memory addresses efficiently. DDR works similarly.

Another part of the process is precharging, where we prepare the memory for subsequent operations. We use the WE (write enable) line to initiate a precharge cycle (tRP). After completing this interval, we can select the next row address. There is also a constraint (tRAS) on how long a row must remain active before precharging again. Refresh scheduling is important, as we need to refresh every ~64 ms to prevent data loss; the memory controller manages this using counters.

---

Memory types:

SDR SDRAM: frequency is the same for the memory cell array and the bus. To increase throughput, we would need to increase frequency, which is not feasible.

DDR1: uses the same frequency across components but transfers data on both clock edges, effectively doubling throughput using an I/O buffer.

DDR2: increases bandwidth further by using a faster I/O interface; since the cell array cannot operate at higher frequency, the I/O buffer helps achieve higher effective data rates.

DDR3: the I/O operates at around 4f, and with DDR signaling, achieves effectively higher bandwidth (8× of the cell array rate). It is also more energy efficient compared to DDR2 (based on the context of the paper).

Per channel of DDR1, DDR2, DDR3, we have various numbers of pins (e.g., ~240 for DDR2). DDR2 typically works with up to 2 modules per channel, while DDR3 often supports only 1 module per channel at higher frequencies.

As we are limited by the number of channels from the Northbridge, we could use memory controllers integrated per processor, but this introduces NUMA complications, which are not always desirable. Intel addressed this using another kind of DRAM called FB-DRAM (Fully Buffered DRAM). It uses a serial bus to the memory controller.

Advantages are:

1. More modules per channel can be use
2. More channels per memory controller can be used (narrower interface compared to parallel DDR2 bus)
3. The serial bus is designed to be full-duplex
4. It is feasible to implement differential signaling (two lines in each direction), increasing speed

This results in higher overall throughput (see performance table in the paper), though with added latency.

Some more important ideas: for DDR-based DRAM, we use parallel channels (often dual-channel) from the memory controller to DIMMs (RAM slots where we physically insert RAM sticks). In FB-DRAM, we can support up to ~6 serialized channels, and this increased number helps overcome the serialization/deserialization latency. With higher frequency, this can be a better option, as achieving similar performance on a wide parallel bus at high frequency is energy inefficient and difficult to maintain.
